# 미완성 기능 전체 목록

2026-10-13 사용자 요청("우리 미완성 기능 다 정리해, 빠짐없이, codex랑 같이 생각해")으로 만든 점검표예요. [tasks.md](tasks.md)는 작업 하나하나의 진행 기록이고, 이 문서는 "지금 빠져 있거나 반쯤인 것"을 영역별로 한 장에 모은 거예요. 두 쪽이 따로 읽은 목록을 합쳤어요.

- 제가 `tasks.md`, 문서, 코드를 읽어 만든 목록
- Codex(`codex exec`, 읽기 전용)가 저장소 전체를 따로 읽고 만든 목록. Codex의 주장은 그대로 믿지 않고, 버그라고 적은 것은 제가 근거를 다시 확인했어요(맨 아래 "Codex 주장 확인")

상태: **없음**(시작 전), **반쯤**(일부만 됨), **확인 안 됨**(코드는 있는데 VM 밖에서 못 봄), **버그**(근거를 확인함). 우선순위: **P0** 첫 사용자가 지금 막혀요, **P1** 첫 사용자에게 중요해요, **P2** 나중이에요. 작업 번호가 있으면 [tasks.md](tasks.md)에서 이어져요.

## 먼저 볼 것

가장 큰 구멍 여섯 개예요.

1. **보안 부팅(Secure Boot)**: 켜진 채로는 USB가 안 켜져요. 사용자가 펌웨어에서 꺼야 하고, 끄면 BitLocker가 복구 키를 물을 수 있어요. 요즘 PC 대부분이 해당돼요(T-148).
2. **실제 PC 확인이 한 대, 범위를 몰라요**: 사용자가 실기기에서 해 보고 "잘 된다, VMware와 똑같다"고 알려 줬어요. 어떤 PC에서 라이브만 했는지, 설치까지 했는지, 와이파이·소리·절전은 어땠는지 기록이 없어요(T-167).
3. **설치기 화면을 끝까지 눌러 설치해 본 테스트가 없어요**: 설치 테스트는 화면을 거치지 않고 백엔드를 바로 불러요. 화면의 버튼과 백엔드 연결이 깨져도 못 잡아요(T-171).
4. **실제 윈도우 디스크 옆 설치**: 가짜 EFI·NTFS 디스크로만 확인했어요. 진짜 윈도우의 GRUB 항목, BitLocker, OEM 복구 파티션은 몰라요(T-006).
5. **노트북 기본 동작**: 잠자기 단추와 배터리일 때의 자동 절전은 생겼어요(2026-10-14). 시간을 바꾸는 설정과 실제 노트북에서 깨어나는지는 아직이에요(T-172).
6. **설정 앱이 개인 설정·소리·와이파이·블루투스·정보뿐이에요**: 해상도, 여러 모니터, 날짜와 시간, 키보드, 터치패드, 사용자, 기본 앱, 전원, 업데이트가 없어요(T-149, T-173).

| 재현 가능한 빌드 | 없음 | ISO를 개인 PC에서 수동으로 빌드하고 서명해요. 같은 소스에서 같은 ISO가 나오는지 다른 사람이 못 확인해요 | P2 |

| 디스크 암호화(LUKS) | 없음 | GRUB이 LUKS2를 못 여는 문제, 스냅샷 부팅과의 조합을 조사해야 해요(T-163) | P1 |
| 재설치할 때 `/home` 지키기 | 없음 | 이전 RobinOS 파티션을 다시 쓰면 전체를 포맷해요. 개인 파일도 지워져요(확인 상자는 있어요) | P1 |

| 설치 언어 고르기 | 없음 | `ko_KR.UTF-8` 고정. 시간대는 이번에 고를 수 있게 했어요 | P2 |

| 설치기에서 보안 실습 프로필 고르기 | 없음 | 설치한 뒤 `robinctl profile`로 해요 | P2 |
| 암호화·보안 부팅·Plymouth를 함께 설계 | 없음 | 셋 다 GRUB과 스냅샷 부팅에 걸려요. 하나씩 넣으면 서로 깨질 수 있어요 | P1 |

## 이번에 고친 것 (2026-10-13)

[T-171](tasks.md)과 이 점검에서 고친 것이에요. VM 검증을 거쳐 푸시해요.

- 설치 진행률이 패키지 설치 내내 12%에 멈추던 것, 화면의 BitLocker 확인이 전달되지 않던 것, 멈춘 설치를 다시 못 하던 것, 윈도우가 다른 디스크에 있을 때 부팅 메뉴에 안 나오던 것
- ISO의 EFI 파티션 이름 `ARCHISO_EFI`, 설치본 콘솔의 "Arch Linux" 문구
- 압축 스왑(zram)
- `robinctl update --preview`가 업데이트 확인에 실패해도 "모두 최신이에요"라고 하던 것(`checkupdates` 종료 코드 1을 구분)
- 설치본에 `bolt`(Thunderbolt 승인) 추가. 라이브에는 있었고 설치본에는 없었어요
- 설치 테스트가 Flathub 저장소가 설정돼 있는지 조건으로 확인
- `desktop.md`의 시간대 설명, `testing.md`의 장면 수, README의 내려받기 버전(v0.3.0)
