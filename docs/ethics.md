# RobinOS 윤리 기준

RobinOS는 합법적인 보안 학습, 허가받은 테스트, CTF 연습, 방어 연구를 위한 OS예요.

해야 할 것:

- 로컬 랩, CTF 플랫폼, 직접 소유한 시스템에서 연습하기
- 실제 대상을 테스트하기 전에 명확한 서면 허가 받기
- 허가받은 점검에서는 기록을 남기고 범위를 정해 두기
- 방어 관점의 이해와 책임 있는 공개(responsible disclosure)를 우선하기

하면 안 되는 것:

- 허가 없이 시스템 공격하기
- 자격 증명, 토큰, 쿠키, 개인 데이터 훔치기
- RobinOS 기본 구성에 지속성 확보, 탐지 회피, 은밀한 접근 기능 넣기
- RobinOS로 사람, 서비스, 조직에 피해 주기

RobinOS에서는 위험한 행동보다 안전하게 배우는 쪽이 더 쉬워야 해요.

## 실습 랩의 안전 기준

- 취약한 실습 앱은 `127.0.0.1`에만 열어요. 같은 네트워크의 다른 컴퓨터에서는 보이지 않아요.
- 랩은 `robinctl lab start`로 켤 때만 돌고, 재부팅해도 저절로 켜지지 않아요. 브라우저로 다른 사이트를 보는 동안 취약한 앱이 켜져 있는 시간을 줄이기 위해서예요.
- 사용자를 `docker` 그룹에 넣지 않아요. 그 그룹은 비밀번호 없는 관리자 권한과 같아서, 내 계정으로 도는 프로그램 하나가 뚫리면 시스템 전체가 넘어가요. 랩을 켜고 끌 때만 `sudo`로 비밀번호를 물어요.
- 리버싱 미션의 연습 프로그램은 RobinOS가 직접 만든 것이고 소스(`practice/reversing`)가 공개돼 있어요. 코드를 보여 주는 것 말고는 아무 일도 하지 않아요. 다른 프로그램을 분석할 때는 라이선스가 허락하는지 먼저 확인하고, 출처를 모르는 프로그램은 VM 안에서 열어요.
- 웹 기초 미션의 연습 서버는 `127.0.0.1`에만 열려요. robots.txt 읽기 같은 웹 점검의 첫걸음도 내 연습 서버와 허가받은 곳에서만 해요.
- 입문 CTF(`robinctl ctf`)의 문제는 모두 `~/practice/ctf`의 파일과 내 연습 서버에 있어요. 5번의 쿠키 바꾸기도 내 연습 서버에서만 해요. 남의 사이트의 쿠키를 바꿔 권한을 얻는 건 허가 없는 공격이에요.
- 미션의 로그와 IP 주소는 지어낸 것이고, 주소는 문서용으로 정해진 범위(RFC 5737)만 써요.

## 기본 설치의 네트워크

- 기본으로 켜 두는 네트워크 서비스는 인쇄(CUPS)와 같은 네트워크의 프린터 찾기(Avahi)뿐이에요. 원격 접속(sshd)은 꺼져 있어요.
- CUPS는 내 컴퓨터 안에서만 받아요(`localhost:631`과 소켓 파일). 다른 컴퓨터가 내 프린터를 쓰거나 프린터를 등록하게 하는 공유와 `cups-browsed`는 넣지 않았어요.
- Avahi는 같은 네트워크에 컴퓨터 이름을 알리고 5353/udp로 답해요. 공공 와이파이에서 이름을 알리고 싶지 않으면 `sudo systemctl disable --now avahi-daemon.service avahi-daemon.socket`으로 꺼요. 그러면 네트워크 프린터를 자동으로 찾지 못해요.
